# Vancouver Directory

Express + Prisma + PostgreSQL directory site with server-rendered Nunjucks templates. Plain
JavaScript, no bundler. Project-specific rules only — the user-global base applies on top.

Vault lane: **vancouver-directory**

## Layout

| path | what |
|---|---|
| `server.js` | entry point (`npm start`), Nodemon in dev |
| `src/` | application code: routes, scripts, data QA |
| `prisma/` | schema, migrations, `seed.js` |
| `views/` | Nunjucks templates |
| `public/` | static assets and generated image variants |
| `src/scripts/check-*.js` | the design/QA gate (see below) |
| `src/data-qa/` | baseline and comparison harnesses |

## Commands

```powershell
npm start                  # node server.js
npm run dev                # nodemon
npm run db:generate        # prisma migrate dev --name init
npm run db:migrate         # prisma db push
npm run db:seed            # seed data
npm run check              # the gate: design tokens, photo states, copy, CSP, wiring
npm test                   # check + image-variant validation
npm run scrape:venues      # data ingestion
npm run qa:baseline        # capture a data-QA baseline
npm run qa:compare         # compare against it
npm run build:images       # generate image variants
```

## Rules

- **`npm run check` is the definition of done**, not an optional extra. It chains ten scripts
  covering design tokens, photo states, consumer copy, concierge variety, CSP interactions,
  swap wiring, studio dock, hoods, and error leaks. A change that breaks it is not finished.
- **Prisma postinstall is gated by npm 11.** A fresh `npm ci` leaves `@prisma/client` and
  `@prisma/engines` without their generated engines. Run the postinstalls by hand:

  ```powershell
  node node_modules\@prisma\engines\scripts\postinstall.js
  node node_modules\@prisma\client\scripts\postinstall.js
  ```

  Without them, Prisma fails at runtime with missing-engine errors.
- `db:migrate` uses `prisma db push`, which is destructive to schema drift. Never run it against
  data you care about without confirming the target database first.
- `public/` image variants are generated by `build:images`; don't hand-edit generated variants.
- Scrapers hit live external sites. Don't run `scrape:full` as a smoke test.
- `node_modules/` is generated: rebuild with `npm ci`.

## Before calling work done

1. `npm test` passes (which includes `npm run check`).
2. If the schema changed: `db:generate` and verify the client still matches.
3. If templates or copy changed: the copy and design-token checks in `npm run check` cover it.
4. Record decisions worth keeping with `append_decision` on lane `vancouver-directory`.
